# astrbot_plugin_rutodistill 世另我

`astrbot_plugin_rutodistill`（**世另我**）是一个基于 **AstrBot v4.x** 最新 API（建议兼容 `≥4.11.4`）的人格蒸馏插件。

通过多轮交互自动萃取目标用户的语言风格、认知模式、价值观与行为习惯，并在后续对话中**自动拟态**对方的表达方式——包括标点、空格、括号表情等格式习惯。

---

## ✨ 核心特性

- **两种使用模式**：
  - `/r-start`（蒸馏学习）：边对话边由后台异步任务萃取用户语言风格与价值观；**首次进入会自动抛出随机话题**引导对话。
  - `/r-lock`（静态锚定-拟态）：锁定当前 Profile 为只读，持续以已蒸馏特征拟态对话。
- **全异步无感解耦**：蒸馏分析逻辑通过 `asyncio.create_task` 提交后台执行，**绝不阻塞主回复链路**。
- **自动拟态、去人机味**：无论是否已蒸馏出特征，对话都会注入「自然闲聊」风格约束，避免分点、表格、教程与客服套话；蒸馏出特征后自动叠加拟态，**严格模仿目标用户的标点与格式习惯**（是否用标点、空格分隔、括号表情等）**与思维方式**——无需用户提醒。开场词、口头禅等语言细节不做硬性约束，交给模型像真人一样根据语境自然判断。
- **Profile 完整重写、清晰连贯**：每轮提取由 LLM 基于已有特征 + 最新输入输出**完整重写**后的表述（而非增量拼接），Profile 各字段始终保持语法正确、结构清晰、用词精炼。
- **收敛度客观科学**：收敛度基于「最近 N 轮特征的实际变化幅度」（字符串相似度客观计算）得出——特征仍在大幅变化时不会虚高，只有特征稳定后收敛度才接近 1。
- **降级保护机制**：LLM 提取 JSON 失败或网络波动时自动静默降级，不中断主流程对话。
- **数据安全持久化**：数据全部存储在 `data/plugin_data/astrbot_plugin_rutodistill/`，带原子落盘与并发锁保护。

## 🎮 指令说明

| 指令 | 说明 |
| --- | --- |
| `/r-start` | 初次使用，默认进入「蒸馏学习」模式；**首次进入会自动抛出一个随机话题**引导对话；若已有蒸馏数据，会提示是否初始化（`/r-start reset` 确认清空重来） |
| `/r-lock` | 切换至「静态锚定-拟态对话」模式：Profile 锁定只读，持续以已蒸馏特征拟态对话 |
| `/r-status` | 查看当前蒸馏轮数、收敛度及 Profile 特征卡片 |
| `/r-info` | 查看当前 Provider 启用的模型列表并设置/清除蒸馏模型（支持序号或模型名） |
| `/r-export` | 导出可直接粘贴进 AstrBot 人格设定的人设 Prompt（markdown）；`/r-export json` 可输出原始 Profile 数据 |

> 指令消息会被自动识别并**跳过蒸馏**，不会被当作个人风格学习。普通对话消息才会参与蒸馏。

## ⚙️ 配置项 (`_conf_schema.json`)

在 AstrBot 插件配置面板中可调节以下参数：
- `distill_model`: 蒸馏模型指定。配置面板中会渲染为**下拉选择框**（AstrBot 启动后自动从当前 Provider 启用的模型中填充选项）；留空则跟随 Provider 默认模型。也可在聊天中使用 `/r-info` 指令从当前 Provider 启用的模型中直接选择。
- `detail_merge_interval`: 细节库定期无损整理周期（每天/每三天/每周/每半个月/每个月/从不，默认每周）。细节库**不设存储上限**逐条累积；每轮蒸馏后按周期检查可合并的重复/近义条目并**无损合并**（保持顺序、其余逐字保留、不概括不丢信息）。选择「从不」则仅保留写入时的精确去重。

> 蒸馏模型的生效优先级：**会话级 `/r-info` 设置 > 全局配置 `distill_model` 首个候选 > Provider 默认模型**。

## 🔒 隐私与数据管理

- 所有数据完全保存在本地 `data/plugin_data/astrbot_plugin_rutodistill/` 目录中。
- 用户可随时使用 `/r-start reset` 清空个人蒸馏数据并重新开始。

## ✅ 如何验证插件正常工作

### 1. 基础验证（安装与指令）

1. 在 AstrBot 管理面板确认插件已**启用**、无报错；查看 AstrBot 日志确认无 `Failed to load plugin` 记录。
2. 依次发送 `/r-start`、`/r-lock`、`/r-status`，应分别得到对应的模式切换/状态卡片回复，**说明指令路由与状态持久化正常**。
3. 发送 `/r-info`，应列出**当前 Provider 启用的模型**，并能用 `/r-info 序号` 或 `/r-info 模型名` 设置、`/r-info clear` 清除。

### 2. 核心功能验证（蒸馏）

1. 确保处于 `/r-start` 蒸馏模式（首次进入会自动抛出一个随机话题）。
2. 顺着话题或主动连续发送 **10~20 条风格鲜明的消息**（不同句式、口头禅、观点），等待数秒。
3. 发送 `/r-status`：`蒸馏轮数` 应随消息增长；**收敛度反映真实进度**——当你的表达风格还在明显变化时收敛度较低，随着风格逐渐稳定（连续多轮特征基本不变）收敛度才趋近 100%。
4. 检查数据落盘文件：
   `data/plugin_data/astrbot_plugin_rutodistill/<会话ID>.json`
   `profile` 下的 `style`/`cognition`/`values` 等字段应出现与你的表达风格匹配的**完整、清晰的描述**，`metrics.turns_count` 应为正数。
5. 发送 `/r-export`，应导出一份**可直接复制粘贴进 AstrBot 人格设定**的 markdown 人设 Prompt（`/r-export json` 可查看原始 Profile 数据）。

> 蒸馏为**后台异步任务**，回复本身不等待蒸馏结果，因此请稍等片刻再查 `/r-status`。

### 3. 自动拟态效果验证

1. 完成步骤 2 积累一定特征后，继续闲聊（蒸馏模式或 `/r-lock` 锁定模式下均可）。
2. **无需任何提醒**，观察机器人回复是否自动贴近你的表达习惯——尤其是**标点/空格/括号表情等格式习惯**、口头禅、句长与语气。
3. 对比 `/r-lock` 前后的差异：锁定后 Profile 不再更新，拟态效果保持稳定。

### 4. 注入与降级验证

- 在蒸馏或锁定模式下，AstrBot 发出的 LLM 请求应带有插件注入的拟态 System Prompt（可通过 AstrBot 的调试/请求日志观察）。
- 临时把 Provider 密钥改错再发消息：**主对话不应崩溃**，插件只会在日志中记录 `[rutodistill]` 的 debug 级错误并自动跳过蒸馏。

### 5. 持久化与健壮性

- 重启 AstrBot 后再次发送 `/r-status`，蒸馏轮数、Profile 应**完整保留**。
- 发送 `/r-start reset` 后，Profile 与指标应被清空并重新开始蒸馏。

### 常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| `/r-info` 无模型列表 | 未配置可用的对话 Provider，或 Provider 不支持 `get_models()`；可改用模型名直接指定 |
| 蒸馏轮数不增长 | 确认处于 `/r-start` 蒸馏模式；指令消息会被自动跳过；查看日志中 `[rutodistill]` debug 输出 |
| `/r-status` 中 Profile 为空 | 蒸馏 LLM 输出未通过 JSON 解析时会被静默丢弃（降级保护），多积累几条风格消息后再观察 |
| 重启后数据丢失 | 确认插件运行目录下存在 `data/plugin_data/astrbot_plugin_rutodistill/` 且文件可写 |
